# T-0018: Modern document validation — test round-trip fidelity with Office 365 / Copilot-generated documents

**Status**: DONE | **Size**: M
**Phase**: DONE
**Blocked by**: T-0015 (completed -- added w16du and w16sfl namespaces)

## Context
Microsoft 365 with Copilot has introduced new document creation workflows (agent mode, direct editing, image interpretation). While these use standard OOXML, Copilot-generated documents may favor certain patterns (structured headings, content controls for templating) or include newer namespace extensions. We need to validate that our fork handles modern Office 365 output correctly.

Since actual Copilot-generated documents cannot be obtained programmatically, this task creates synthetic test documents that exercise the new namespace extensions added in T-0015 (w16du, w16sfl) alongside existing extension features.

## Acceptance Criteria
- [x] Create synthetic test documents exercising modern namespace extensions
- [x] Verify w16du:dateUtc attribute preservation on round-trip
- [x] Verify w16sfl:formattingAllowed attribute preservation on round-trip
- [x] Verify combined extension features in a single document
- [x] All tests pass: `pytest tests/ -q`
- [x] Verify no unknown namespace warnings or element drops
- [x] Confirm all extension features (SDT, fields, bookmarks, etc.) work with modern namespaces

## Approach
1. Use `parse_xml` with `nsdecls` to create XML fragments containing modern namespace attributes
2. Inject them into Document objects via the underlying lxml element tree
3. Save to `BytesIO` and reload to test round-trip fidelity
4. Verify attributes survive using `qn()` for namespace-qualified attribute lookups

### Key findings
- lxml preserves all namespace-qualified attributes through serialization/deserialization without any special handling needed
- The namespace URIs registered in `ns.py` (from T-0015) are sufficient for attribute lookup via `qn()`
- No element drops or namespace warnings occur during round-trip
- Extension namespace attributes on elements that have registered custom classes (like `CT_RunTrackChange` for `w:ins`) are preserved correctly -- the custom class metaclass does not strip unknown attributes
